# Формуляр відвідувача

Повноцінний приклад взаємодії фронтенду та Node.js/Express сервера для збору контактних даних, відправлення OTP-кодів та підтвердження номерів телефону з базовими механізмами безпеки.

## Структура

- `src/web/` — статична HTML-сторінка з формою, логікою виклику локальних API та локальним журналом подій.
- `src/server/` — Express застосунок зі збереженням даних у SQLite, OTP-флоу та допоміжними сервісами (логер, інтеграція з SMS-провайдером).

## Налаштування та запуск сервера

1. Перейдіть у директорію сервера та встановіть залежності:

   ```bash
   cd src/server
   npm install
   ```

2. Створіть файл `.env` на основі [`src/server/.env.example`](src/server/.env.example) та при потребі оновіть значення (порт, список дозволених доменів, параметри OTP тощо).

3. Запустіть сервер:

   ```bash
   npm start
   ```

   Сервер буде слухати порт, вказаний у `PORT` (за замовчуванням `4000`).

4. Відкрийте `src/web/index.html` у браузері або підніміть будь-який статичний сервер, щоб завантажити форму. Для коректної роботи CSRF-куків сторінка має бути відкрита з того ж походження, що й API, або домен має бути в `ALLOWED_ORIGINS`.

## API

Усі маршрути знаходяться під префіксом `/api` і захищені CSRF-токеном (`GET /api/csrf-token`).

- `POST /api/feedback` — зберігає контактні дані у таблиці `submissions`, перевіряє унікальність телефону й автоматично позначає перший запис як учасника розіграшу.
- `POST /api/send-otp` — генерує та надсилає (через інтеграцію-плейсхолдер) SMS-код, створює запис у таблиці `phone_otps`, застосовує таймер придатності та rate limiting.
- `POST /api/verify-otp` — перевіряє код, оновлює статус `sms_verified` у `submissions` та відмічає OTP як підтверджений.
- `GET /api/health` — технічний стан сервісу.

## База даних

Схема автоматично створюється у файлі `src/server/data/app.db` (SQLite):

- `submissions` — дані форми (ім’я, прізвище, телефон, email, компанія, географія, технічні метрики, прапорець участі в розіграші, статус SMS-підтвердження).
- `phone_otps` — OTP-коди, термін дії та мітка підтвердження.

Журнал подій зберігається у `src/server/data/events.log`.

## Безпека та обробка помилок

- CORS з білим списком доменів (`ALLOWED_ORIGINS`).
- Rate limiting (параметри `RATE_LIMIT_WINDOW_MS`, `RATE_LIMIT_MAX`).
- CSRF-захист на основі куків та токена.
- Стандартизовані відповіді на помилки (400/403/404/409/429/500) та журналювання подій (успішні дії та помилки).

## Клієнтський скрипт

Сторінка у `src/web/index.html` використовує локальні API, керує процесом надсилання форми та OTP, веде локальний журнал дій у `localStorage` та відображає повідомлення користувачу.
